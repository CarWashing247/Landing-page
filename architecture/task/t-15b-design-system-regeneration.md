# T-15B · Design system regeneration

## Goal

Replace the Canva-derived design with one generated by the `ui-ux-pro-max`
skill, so there is exactly one design source in the repo and it is a file rather
than a link to someone's account.

> **Superseded for visual decisions by
> [`phase3-uiux-promax.md`](../phase3-uiux-promax.md) (T-15C).** What this task
> established still holds — one committed design source instead of a third-party
> account, no hex values in components, contrast measured in a browser — but the
> palette, type pairing and radii it introduced were replaced one revision later.
> `MASTER.md` remains in the repo as the record of that step.

## Why

The Canva decks were an external dependency on a third-party account: they could
not be diffed, reviewed in a PR, or read by anyone without access, and their
text extraction was OCR-damaged in ways that nearly shipped typos (T-15A found
"Bằng giả" for "Bảng giá"). A generated system committed to the repo is
reviewable, versioned and offline.

## What changed

| | Canva (retired) | `MASTER.md` (now) |
| --- | --- | --- |
| Primary | `#0B1F33` navy | `#059669` green |
| Accent | `#29C8B5` teal | `#EA580C` orange |
| Background | `#F3F6F8` grey | `#ECFDF5` mint |
| Text | `#071522` ink | `#064E3B` deep green |
| Shadows | named, no values | four levels with values |
| Type scale | six roles | **not specified — the existing scale is kept** |

Token names changed with the palette: `ink` → `foreground`, `surface` →
`background`, `white` → `card`, `highlight` → `secondary`, plus `muted`,
`border`, `destructive` and `ring`, which did not exist before.

## Scope

**In scope**

- `design/phase3/`, generated and committed.
- `src/app/globals.css` rebuilt from it: palette, shadows, reduced-motion.
- Every component migrated to the new token names.
- A logo mark and a favicon from the generated logo brief.
- Design.md and every Phase 3 task file repointed at the new source.

**Out of scope**

- Restyling components beyond the token swap. The header, footer, blocks and
  service page keep their current structure; applying the generated system's
  Funnel pattern and component specs to each is the follow-on work listed under
  "What this does not do".

## What this does not do

The palette and tokens are replaced; the **layouts are not redesigned**. Still
outstanding, each against `MASTER.md`:

- **Website UI** — the generated system specifies a Funnel (3-step conversion)
  pattern, Swiss/minimalist style, card and button specs and a subtle scroll
  reveal. T-16, T-17, T-17A, T-18 and T-19 each need a pass to match.
- **Payload CMS admin** — T-19A, which should now follow `MASTER.md` rather than
  the Canva admin deck it was written against.
- **Motion** — the system asks for a subtle scroll reveal; nothing implements it
  yet, and `prefers-reduced-motion` is already honoured globally so adding it is
  safe.

## Acceptance criteria

- [ ] No component carries a hex value or a retired token name.
- [ ] Every text/background pair in the shell measures at least 4.5:1.
- [ ] `design/phase3/` is the only place a colour is chosen.
- [ ] The site makes zero requests to `fonts.googleapis.com`.
- [ ] A visible focus indicator survives.

## Verification

```bash
grep -rnoE "\b(bg|text|border|ring)-(ink|surface|white|highlight)\b" src --include=*.tsx  # expect none
grep -rn "#[0-9a-fA-F]\{3,6\}" src/components --include=*.tsx                             # expect none
npm run build && npm run start &
curl -s localhost:3000/ | grep -c 'fonts.googleapis.com'   # expect 0
```

Contrast is measured in a real browser against computed styles, not estimated
from the hex values — a token can be overridden by a utility and still look fine
in a screenshot.

## Notes

- **Two places this deliberately departs from `MASTER.md`**, both because a
  binding repo rule outranks a generated suggestion. It offers a Google Fonts
  `@import`, which would break T-15's zero-third-party-font-request criterion and
  the metric-matched fallback that keeps CLS at 0 — `next/font` keeps that job.
  And its `.input:focus` sets `outline: none` with only a `box-shadow` ring,
  which is not painted in forced-colors mode and contradicts the skill's own
  priority-1 accessibility rule; the `:focus-visible` outline stays.
- **The type scale is kept because the generated system does not specify one.**
  `MASTER.md` names the font family and a 16px input size and stops. Deleting a
  working six-role scale to replace it with nothing would be worse.
- The logo mark carries **no text**: the brand name lives in
  `SiteSettings.brandName`, so the header composes the mark with live text and
  renaming the business stays a CMS edit.

## Flags

- **Two real contrast failures were introduced by the palette swap and fixed
  here**, both found by rendering the page and measuring rather than by reading
  the hex table:
  - The active-locale marker was `text-accent` on the header. Teal on navy was
    fine; **orange on green measures 1.06:1** and was effectively invisible. It
    is now marked by weight and an underline rather than by hue — which is the
    better answer regardless, because colour alone should not carry state.
  - Headings were `primary` on the background: **3.5:1**, passing only because
    headings are large text and failing the moment one is set smaller. They are
    now `foreground`, at 9.23:1.
- **The brand changed colour.** Navy and teal became green and orange. That is a
  visible, externally-noticeable change and it came from the generator's
  "hyperlocal services" profile, not from a brand decision anyone recorded.
  Worth confirming before launch.
- Any printed material, social avatar or Google Business Profile image still
  carries the old navy mark. Nothing in this repo knows about those.
